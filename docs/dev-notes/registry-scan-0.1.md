# Разбор реестров проверок 0.1 — заметки испытаний

## Проверено

- `npm test` — 13 тестов на вымышленных реестрах (4 альбома, шаблон v3 и ранний с другим порядком столбцов): основы слов, приведение формулировок, документ нормы, ссылки на листы, пропуск ложных и снятых, сходство, независимость групп от порядка, чтение реестра, временные файлы Excel, кандидаты (3 альбома — да, 2 — нет, 5 раз в одном альбоме — нет), черновик до 300 знаков, отчёт, csv, записи шага 0 проходят проверку навыка, командная строка от начала до конца.
- `npm run typecheck` — без ошибок.

## Не проверено — нужны реальные реестры

Проверки на реальных реестрах нет: деперсонализированный пример ещё не передан (`docs/questions.md`, вопрос 3), а искать реестры на диске руководителя автоматический режим не разрешил (личные данные). Что проверить, когда будут копии:

- порог сходства 0,45: не склеивает ли разные замечания и не дробит ли одно — подобрать на 2–3 десятках реестров;
- доля замечаний с кодом ТН-xx и без него;
- черновики записей: годятся ли как есть или Claude при разборе переписывает почти все;
- скорость на сотнях реестров (сравнение замечания со всеми группами — квадратичное; на тысячах замечаний — секунды).

## Решения по ходу

- **Повтор считается по разным альбомам**, а не по числу замечаний: одно замечание на десяти листах одного альбома — ошибка альбома, не бюро. Рабочий вариант — `docs/questions.md`, вопрос 13.
- **TypeScript без сборки**: Node.js 22.18+ запускает `.ts` сам; `tsc` — только проверка типов. Сборка (как в Schema Teams) появится с сервисом в задаче 4.
- **ExcelJS 4.4.0** тянет старый `uuid` с уязвимостью средней тяжести (`npm audit`); подставлен `uuid` 11 через `overrides` — ExcelJS работает, `npm audit` чист.
- `package-lock.json` исключён из проверки на реальные данные: в нём сообщения авторов пакетов с адресами почты. Проверка теперь смотрит и новые, ещё не добавленные в git файлы — раньше вымышленные образцы в тестах навыка прошли незамеченными до `git add`.
