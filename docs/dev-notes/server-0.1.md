# Основа сервиса 0.1 (задача 4б) — заметки испытаний

## Проверено

- `npm run check` — генерация клиента базы, проверка типов, 69 тестов, проверка на реальные данные.
- 20 сквозных тестов сервиса на временной PostgreSQL 16 через HTTP: двойной контроль, права токенов, поиск и счётчик запросов (в том числе у ожидающих записей), отметки по людям и «ложная» с двух отметок, противоречие фактов, замена правила, вопрос без модерации и повтор вопроса, ответ на вопрос, пометка «проверить» и её снятие, правка с проверкой версии, связи и граф, список для разбора, «B25» → «В25», вход в веб и выход, отзыв токена, импорт md (повтор безопасен), датасет без токенов, страница справки, ограничение отправок.
- Запуск вживую на временной базе: `cli.ts moderator`, `project add`, `main.ts` — `/api/health`, вход по токену, журнал без текста записей.

## Не проверено

- **Docker.** На компьютере разработки Docker нет: `Dockerfile` и `deploy/docker-compose.yml` проверятся при установке на сервер (задача 5).
- **Синхронизация проектов со Schema Teams** не сделана — проекты добавляются командой; нужен токен Schema Teams только на чтение.
- **Реальные данные пилота** — после пилота навыка «Выводы» (импорт md его папок).

## Решения по ходу

- **TypeScript без сборки** и в сервисе: Node.js 24 в образе запускает `.ts` сам, клиент Prisma генерируется с импортами `.ts`. Сборки `dist` нет — меньше шагов при обновлении на сервере.
- **Тесты** — встроенный `node --test`, без Vitest; база — `embedded-postgres`, как в Schema Teams (ADR 001 уточнён).
- **Противоречие с правилом бюро** хранится связью «противоречит», пока запись на модерации: так модератор видит, с каким правилом спор. Принять такую запись нельзя — только «заменить» правило или «отклонить» (`packages/core/src/rules.ts`).
- **Похожий открытый вопрос** определяется полнотекстово по всем значимым словам (от 4 букв, не меньше двух слов) — грубо; уточнить на пилоте.
- **Уязвимости `npm audit`** (`deepmerge-ts`, `mysql2`) — в служебной программе Prisma, которая нужна только для генерации клиента; рабочий сервис её не вызывает. Как в Schema Teams.
- **Предупреждение `pg`** «client.query() when the client is already executing a query» идёт изнутри драйвера Prisma в транзакции; безвредно до `pg` 9, следить за обновлениями `@prisma/adapter-pg`.
- Дата на странице справки и в разборе реестров — по местному времени (было по UTC — вечером показывалось вчерашнее число).

## Веб (задача 4г)

- Проверено во встроенном браузере на локальном стенде (`npm run dev:local`, вымышленные записи): вход по токену, список с пометками «проверить» и «противоречие», карточка с историей, «Принять» по записи с противоречием, подсказка похожих записей при вводе, настройки (версии ПО, сотрудники, токены); на ширине телефона 375 px — без горизонтальной прокрутки.
- Не сделано: экран графа (этап 4 плана, параллельно с пилотом), правка ядра и проекта в карточке (через API есть), отзыв токена — без подтверждения.
- Адреса веба — через `#`, без библиотеки маршрутов; запросы — без библиотек, `fetch`.

## Граф (этап 4)

- Проверено во встроенном браузере на стенде: весь граф (записи по ядрам, противоречие — красный пунктир, «проверить» — жёлтая рамка), щелчок — запись в панели, «граф вокруг» на 2 шага.
- Найдено и исправлено: раздача веба брала только файлы, что были при запуске сервиса (`wildcard: false`) — новый файл графа после пересборки отдавался как страница; теперь файлы ищутся при каждом запросе.
- Библиотека графов (~440 КБ) грузится отдельно, только при открытии графа; основной файл веба — ~245 КБ.
- На сотнях записей не проверено — раскладка `cose` может быть медленной; смотреть на пилоте.
