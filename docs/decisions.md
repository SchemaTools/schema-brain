# Решения

Что решено руководителем и не пересматривается без него. Новые решения — в конец, с датой. Формулировки руководителя — в кавычках.

## 2026-10-14 — концепция

- Сервис на сервере бюро, в Docker, доступ из локальной сети офиса; работа из дома — позже.
- Модель данных — граф: записи и типизированные связи; поиск по смыслу плюс переход по связям.
- Хранение — база, не файлы; для человека — просмотр записей и графа. Выгрузка в md в стиле Obsidian — отдельный этап.
- Подключение агентов — через MCP. Сначала Claude в локальной сети; ChatGPT / Codex — тот же навык и MCP сразу (всё в локальной сети, внешний адрес не нужен). Локальные модели — потом.
- В сервис попадает только то, что сотрудник отправил сам; личные чаты агентов не попадают. Личной области нет: «личное в систему попадать не должно вообще». Области — проект и бюро.
- Двойной контроль: автор подтверждает запись в своём агенте, модератор — на сервисе. Модератор на старте — руководитель. Поле «подтверждено автором» у записи.
- Порога подтверждений для области «бюро» нет: «чем больше проверяющих, тем быстрее база наполнится».
- Массив данных для дообучения локальных моделей копить с первого дня; разбор массива — руководитель, периодически.
- Сценарии — все три: общая память о бюро, передача контекста по проектам, накопление опыта.

## 2026-10-14 — итоги штурма (16 решений в первую версию)

- Навык «Выводы» — вход всей системы; стартует на md-файлах до сервера; для ChatGPT / Codex — тоже.
- Запись типизированная: до 300 знаков, вид (факт / правило бюро / гипотеза), ядро, проект, версия ПО, «когда не применимо»; предлагается по событию внутри сессии, не больше трёх за сессию.
- Срок годности по версии: при смене версии — пометка «проверить», показатель не сбрасывается.
- Показатель доверия `n/(n+b+1)` (n — «сработало», b — «не сработало»); «при 25 % и менее считать ложным». Подтверждение — делом, через агента.
- Выводы-соперники — только для фактов и гипотез; для правил бюро один ответ; «отдавать различия на модерацию».
- Подсматривание — по ходу задачи, не только в начале.
- Открытый вопрос — отдельный тип записи; отвечает сначала руководитель, «потом при росте подключаем других».
- Отдельной «страницы входа» нет — Schema Brain питает справку Schema Teams.
- Ядра на старте: Проектирование · BIM и Revit · Процессы бюро · Инструменты (плагины, навыки, MCP); добавления предлагает Claude при разборе. Оси: ядро обязательно, проект (из Schema Teams) при необходимости.
- Реестры проверок — источник кандидатов «типовая ошибка» (повтор ≥ 3).
- Обратный ход: подтверждённые правила ядра BIM → правки стандарта и навыков, при периодической ревизии.
- Очередь модерации с приоритетом: противоречия → запрошенные → остальные; счётчик запросов у записи.
- Вход без агента — веб-форма; бот с ответами — после Telegram и локальной модели.
- Отклонено: журнал подсматриваний (вместо него счётчик), модерация из Telegram, сервис сам ставит задачи на проверку, отключение собственной памяти агентов, привязка вывода к задаче Schema Teams, срок у спора, порог подтверждений для области «бюро», подсматривание только в начале.
- Отложено: Telegram, локальные модели и очередь задач для них, «ночной сторож» (поиск дубликатов локальной моделью), эмбеддинги локально.

## 2026-10-15 — план реализации

- Код пишет Claude Code; репозиторий `SchemaTools/schema-brain` открытый. Деперсонализация как в Schema Teams: без имён и фамилий, аккаунтов, портов, путей, адресов сервера; данные базы — никогда; названия Schema, Schema Brain остаются.
- Стек и хранение — на усмотрение Claude Code: разбор и рекомендация в задаче 1, утверждает руководитель.
- Установка и обновление сервиса на сервере — по SSH из локальной сети (доступ вне репозитория).
- «Разрыв до сервера минимальный»: сначала основа сервиса — и сразу на сервер, потом сервис дописывается по ходу дела.
- Пилот сервиса стартует сразу после основы, на веб-списке; граф и модерация в вебе — параллельно.
- Пилоты: навык «Выводы» на md — 3–5 дней, 5–6 человек; сервис — 2 недели, 5–7 человек.
- Принципы: код по ТЗ из чата, приёмка — руководитель; ничего личного и серверного в коде и истории; формат md-записи равен формату записи сервиса; каждый этап проверяется на реальных данных; выгрузка датасета с первой версии; испытания — в dev-notes.

## 2026-10-15 — стек и хранение (ADR 001)

- Утверждено: PostgreSQL 16 + pgvector, без графовой СУБД; код — на стеке Schema Teams (TypeScript, Node.js 22, Fastify, Prisma, React + Vite, Vitest).
- Граф: таблица связей в той же базе, обход — рекурсивным SQL, экран графа в вебе — Cytoscape.js; при необходимости — расширение Apache AGE в той же PostgreSQL. Подробно — `docs/adr/001-стек-и-хранение.md`.
- Векторы: «пока без векторов (как вариант через Claude при разборе), потом на локальной модели бюро». Первая версия — полнотекстовый поиск, агент ищет несколькими формулировками, дубли и противоречия по смыслу находит Claude при разборе (`brain_list`, `brain_link`).
- ChatGPT в первой версии «работает через Codex».
- Порог «ложная запись» (показатель ≤ 25 %) применяется с двух отметок: `n + b ≥ 2`. До этого — «нет отметок» или «мало отметок».
