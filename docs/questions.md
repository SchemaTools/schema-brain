# Вопросы к руководителю

Открытые — сверху. Вопрос не блокирует работу: принять разумный вариант, пометить здесь и в коде, продолжать. Закрытые переносить в `decisions.md` с датой.

**РВ** — рабочий вариант, по которому идёт работа до ответа. В `docs/spec.md` такие места помечены **[РВ n]**.

## Открытые

1. **Показатель при нуле отметок.** `n/(n+b+1)` даёт 0 для свежей записи — она попадёт под порог 25 % как «ложная». Предложение: порог применять при `n + b ≥ 1`, до этого показывать «нет отметок». Принято как рабочий вариант до ответа.
   **РВ:** порог при `n + b ≥ 1`. Следствие: одна отметка «не сработало» у свежей записи сразу делает её ложной (0 из 2 = 0 %). Если это слишком строго — `n + b ≥ 2`, правка в одной настройке.
2. **Счёт отметок по людям или по агентам.** У одного сотрудника может быть два агента (Claude и ChatGPT). Предложение: считать по людям — две отметки от агентов одного человека = одна.
   **РВ:** по людям. Дополнительно: отметка самого автора хранится, но в показатель не входит — «подтверждение делом» от коллег. Если считать и автора, свежая запись сразу получит 50 %.
3. **Пример реестра проверок** (xlsx, деперсонализированный) — нужен для `tools/registry-scan` (задача 3).
4. **Доступ к серверу** для задачи 5 — вне репозитория; когда основа готова.
5. **Лицензия открытого репозитория** — без файла лицензии код «все права защищены»; если нужна открытая лицензия, какая.
6. **Папка выводов для шага 0** у каждого сотрудника — одна общая синхронизируемая папка или у каждого своя; откуда сервис будет импортировать.
   **РВ:** у каждого своя папка; импорт по одной папке с указанием сотрудника.
7. **Где считать векторы для поиска по смыслу** (новый, задача 1). Векторы считает отдельная модель. Варианты:
   - **а) модель на сервере бюро** — третий контейнер, работает на процессоре. Тексты не покидают локальную сеть, денег не стоит; качество для коротких русских записей — хорошее, не лучшее. Нужно 1–2 ГБ памяти на сервере.
   - **б) внешний сервис** (например, эмбеддинги от поставщика ИИ) — качество выше, но тексты записей уходят из локальной сети, нужен платный ключ и выход в интернет с сервера.
   - **в) пока без векторов** — только полнотекстовый поиск с русской морфологией, как в базе знаний объекта Schema Teams.

   **РВ:** первая версия работает как «в» (всё готово к подключению модели), к пилоту — «а». «б» — только по вашему решению: это выход данных наружу.
8. **ChatGPT в локальной сети** (новый, задача 1). ChatGPT (веб и приложение) подключает MCP-серверы из интернета, со своих серверов; сервис в локальной сети бюро ему недоступен без выхода наружу. Codex на компьютере сотрудника работает с локальной сетью нормально.
   **РВ:** в первой версии ChatGPT работает через Codex; у кого только ChatGPT — навык «Выводы» на md-файлах (шаг 0), записи импортирует модератор. Открыть сервис в интернет для ChatGPT — отдельное решение, вместе с «работой из дома».
9. **Видят ли все записи всех проектов** (новый, задача 1). **РВ:** да — в бюро 6–20 человек, а в записи попадает только то, что сотрудник сам решил передать. Ограничить по участникам объекта из Schema Teams можно позже, без переделки записей.
10. **Проходят ли модерацию открытые вопросы** (новый, задача 1). **РВ:** нет — вопрос ничего не утверждает и сразу виден всем; автор подтверждает его в агенте, модератор может отклонить (например, если в вопросе личное).
11. **Когда снимается пометка «проверить»** (новый, задача 1). **РВ:** при отметке «сработало» на текущей версии ПО или вручную модератором.
12. **Публикация в справку Schema Teams** (новый, задача 1). **РВ:** сервис готовит страницу в Markdown по ядру, а публикуете вы через Claude и MCP Schema Teams — с предпросмотром. Прямая запись из сервиса в справку — позже, если ручной шаг будет мешать.
