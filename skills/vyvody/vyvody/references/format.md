# Формат записи

Один файл — одна запись. Имя: `ГГГГ-ММ-ДД — <кратко>.md`. Кодировка UTF-8. Сверху — заголовок между строками `---`, под ним — текст записи.

## Поля

| Поле | Обязательно | Значения |
|---|---|---|
| `type` | да | `вывод` или `вопрос` |
| `kind` | у вывода | `факт`, `правило`, `гипотеза`; у вопроса — пусто |
| `core` | да | `Проектирование`, `BIM и Revit`, `Процессы бюро`, `Инструменты` |
| `project` | нет | код объекта из Schema Teams; пусто — запись для всего бюро |
| `software_version` | нет | от чего зависит: «Revit 2026», «Schema.Tools 1.4», «СП 70.13330.2012» |
| `not_applicable` | нет | когда запись не применима, до 300 знаков |
| `source` | да | «сессия ГГГГ-ММ-ДД, задача „…“» — задача в 2–5 словах, без имён и путей |
| `confirmed_by_author` | да | `true` — только после «ок» сотрудника |
| `created` | да | дата `ГГГГ-ММ-ДД` |

Текст — под заголовком: одна-три фразы, до 300 знаков (считаются все знаки с пробелами). Пустые поля оставляй с пустым значением — не удаляй строку.

## Примеры

Записи ниже вымышленные — образцы формы.

### Факт

Файл `2026-10-15 — оси обрезаются при копировании листов.md`:

```markdown
---
type: вывод
kind: факт
core: BIM и Revit
project:
software_version: Revit 2026
not_applicable: для связанных файлов с общими уровнями
source: сессия 2026-10-15, задача «планы этажей, оси»
confirmed_by_author: true
created: 2026-10-15
---
При копировании листов с планами оси обрезаются, если у видов разные зоны обрезки; перед копированием выровнять зоны обрезки по шаблонному виду.
```

### Правило бюро

Файл `2026-10-15 — марки дверей в спецификации.md`:

```markdown
---
type: вывод
kind: правило
core: Проектирование
project:
software_version:
not_applicable:
source: сессия 2026-10-15, задача «спецификация дверей»
confirmed_by_author: true
created: 2026-10-15
---
Марку двери в спецификации ставим по типоразмеру, а не по помещению: одна марка — один типоразмер с одинаковым заполнением и открыванием.
```

### Гипотеза

Файл `2026-10-15 — медленная синхронизация из-за групп.md`:

```markdown
---
type: вывод
kind: гипотеза
core: BIM и Revit
project:
software_version: Revit 2025
not_applicable:
source: сессия 2026-10-15, задача «синхронизация модели»
confirmed_by_author: true
created: 2026-10-15
---
Синхронизация с центральной моделью замедляется в разы, если в модели больше сотни экземпляров одной вложенной группы; после разгруппировки стало быстрее — проверено на одной модели.
```

### Открытый вопрос

Файл `2026-10-15 — стадия в имени файла выгрузки.md`:

```markdown
---
type: вопрос
kind:
core: Процессы бюро
project:
software_version:
not_applicable:
source: сессия 2026-10-15, задача «выгрузка PDF для заказчика»
confirmed_by_author: true
created: 2026-10-15
---
Нужно ли указывать стадию (П или Р) в имени PDF-файла альбома при отправке заказчику, и в каком месте имени?
```

## Как сделать текст лучше

| Было | Стало | Почему |
|---|---|---|
| «Revit глючит с осями, надо аккуратнее» | «При копировании листов оси обрезаются, если у видов разные зоны обрезки; выровнять зоны по шаблонному виду» | условие → что происходит → что делать |
| «Как мы выяснили выше, этот параметр не работает» | «Параметр „Марка“ у вложенных семейств не попадает в спецификацию основного семейства» | понятно без сессии |
| «<Имя коллеги> сказал, что так не делаем» | «Правило бюро: …» (вид — `правило`) | без имён; правило — если сотрудник подтвердил |
| «Объект на <улица>: колонны 400×400» | `project: <код объекта>`, текст — о решении, а не об адресе | название и адрес объекта — только кодом |
| Три мысли в одной записи | три записи или одна — самая полезная | одна запись — одна мысль |
